# 性能观测与结果局限

## 可选观测

```sh
RUASK_TRACE=1 ruask git status
```

stderr 末尾追加一条 `ruask-trace:` JSON，记录单调时间、请求大小及 HTTP 状态等数值。默认关闭，不记录查询、回答、地址或凭据，不改变 stdout 和退出语义。阶段覆盖配置完成、HTTP 开始/响应/首字节、首正文、完整行/命令候选、结束和退出。

Trace 的命令标记只表示符合格式的完整命令候选，不证明正确性。客户端时间不能独立拆分网络、网关排队、服务缓存和模型推理。测量定义及质量核对见[测试说明](testing.md)。

## 显式推理设置

支持 `thinking.type` 扩展的 OpenAI 兼容服务可设置 `OPENAI_THINKING=enabled|disabled`，或用户文件中的 `[openai].thinking`。环境变量优先，未设置时省略字段，继续采用服务默认值；原生 Anthropic 忽略此设置。不支持扩展的服务可能拒绝请求。

当前 CLI 不提供 `reasoning_effort` 配置，也不自动更改用户配置或模型策略。

## 已有结果与采用决定

截至 2026-11-04，性能研究整体科学结论为 **INCONCLUSIVE**，采用决定为保留现有生产 Prompt、默认 Thinking 和流式完整行解析。

部分设置确实测得较低延迟，但尚未同时通过充分的正确性、完整回答质量和安全性验证，因此不能据此默认启用，也不能将结果概括为没有速度收益。

- 第二阶段 Default/Disabled 对照完成 11 对后因新增完整回答质量错误停采，没有完成 48 题覆盖。
- 准确性 Prompt 的真实覆盖只有 48 题中的 5 个不同任务，尚未证明整体质量等价。
- Low effort 仅为研究中继的 3 对诊断，首条正确命令 P50 为 5.17s → 7.50s，P90 为 10.65s → 8.24s；样本不足以证明稳定尾部改善，也未达到 P90 ≤ 5s 目标。
- 结案复核的 10 份回答为 3 正确、3 部分满足、2 确认错误和 2 待裁决。两份 sed 说明范围争议仍待复核，不计作通过或已证实严重安全回归。

小样本、缓存差异及远端负载限制仍存在。本地固定响应回放和客户端微小耗时不能替代真实模型质量、完整回答速度或安全结论。历史记录保留原始评分；本页只概述采用决定，不提供跨服务性能保证。
